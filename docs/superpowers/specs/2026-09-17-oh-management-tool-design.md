# OH 관리 Tool 설계 명세

## 1. 목적

영업사원이 SharePoint의 공용 Excel에 작성한 OH기 신청을 기준으로, 관리자가 기종과 SN을 배정하고 출고와 매출을 기록하는 과정을 로컬 웹앱으로 관리한다. 기존 수작업 파일 기입과 메일 작성의 반복을 줄이고, 파트너사·부·팀·영업사원별 신청·배정·출고·매출 현황을 확인할 수 있게 한다.

## 2. 확정된 제약

- 실제 업무 데이터는 사용자 PC 밖으로 전송하지 않는다.
- 실제 데이터 저장소는 로컬 SQLite 파일이다.
- GitHub에는 소스 코드, 문서, 가상 샘플만 저장한다.
- Vercel은 기능 시연용이며 가상 데이터만 사용한다.
- Vercel 데모에서는 Excel 업로드·다운로드와 실제 데이터 입력을 비활성화한다.
- Power Automate, Power BI, Microsoft Graph API는 사용하지 않는다.
- SharePoint 파일은 사용자가 직접 내려받고 로컬 앱에서 가져온다.
- Outlook 메일은 자동 전송하지 않는다.
- 1차 사용자는 관리자 한 명이다.

## 3. 기술 구조

하나의 Next.js·TypeScript 코드베이스를 두 모드로 실행한다.

### 로컬 운영 모드

- Windows PC의 `127.0.0.1`에서만 접속한다.
- SQLite에 실제 요청, 장비, 배정, 출고, 매출, 감사 이력을 저장한다.
- `.xlsx` 요청 및 재고 파일을 로컬 서버에서 읽는다.
- Excel 원본은 기본적으로 보관하지 않고, 검증 후 정규화한 데이터와 가져오기 이력만 저장한다.
- 조회 결과를 Excel로 내려받을 수 있다.
- Outlook에 붙여 넣을 제목과 본문 또는 `mailto` 초안을 생성한다.

### Vercel 데모 모드

- 코드와 화면을 확인하기 위한 배포다.
- 저장된 가상 데이터만 표시한다.
- 실제 파일 업로드, 자유로운 데이터 입력, 내보내기를 차단한다.
- 화면 상단에 `DEMO — 실제 데이터를 입력하지 마세요` 경고를 항상 표시한다.
- Vercel Authentication으로 Preview와 Production URL 전체를 보호한다.

## 4. 시스템 경계

```text
SharePoint Excel
    │ 사용자가 직접 다운로드
    ▼
로컬 OH 관리 웹앱 ── SQLite
    ├─ 요청 검증 및 등록
    ├─ OH 재고/SN 관리
    ├─ 배정 및 출고
    ├─ 매출 기록
    ├─ 통계 대시보드
    └─ Outlook 메일 문구 생성

GitHub private repository ── 코드와 가상 샘플만
             │
             ▼
Vercel demo ── 가상 데이터·읽기 전용 데모
```

## 6. 업무 상태

요청은 다음 상태를 사용한다.

```text
접수 → 검토 → 일부배정 → 배정완료 → 출고완료
  └──────────────→ 취소
```

- 요청 수량보다 적게 배정되면 `일부배정`이다.
- 요청 수량만큼 배정되면 `배정완료`다.
- 배정된 모든 장비가 출고되면 `출고완료`다.
- 출고된 장비는 다른 요청에 재배정할 수 없다.
- 취소된 요청의 미출고 배정은 해제해야 취소를 확정할 수 있다.

배정 장비는 다음 상태를 사용한다.

```text
배정 → 출고
  └→ 배정취소
```

## 8. Excel 안전 규칙

- `.xlsx`만 허용하고 `.xlsm`, `.xls`, `.csv`는 1차 버전에서 거부한다.
- 확장자, MIME, ZIP 구조, 파일 크기, 시트 수, 행 수를 제한한다.
- 수식을 실행하지 않고 셀의 값만 읽는다.
- 헤더 매핑이 불확실하면 저장하지 않고 사용자에게 확인 결과를 보여준다.
- 동일한 파일 해시와 동일한 행은 중복 가져오기를 경고한다.
- Excel 내보내기에서 `=`, `+`, `-`, `@`로 시작하는 문자열은 수식으로 실행되지 않게 처리한다.
- 업로드 원본은 파싱 완료 후 삭제한다.

## 9. 로컬 데이터 보호

- 앱은 기본적으로 `127.0.0.1`에만 바인딩한다.
- SQLite DB, 백업, 실제 업로드 파일, 실제 내보내기는 Git 추적 대상에서 제외한다.
- DB 파일은 사용자의 Windows 계정만 접근 가능한 폴더에 둔다.
- 매일 첫 실행 시 암호화된 날짜별 백업을 만들고 보관 기간은 30일로 한다.
- 월 1회 별도 폴더에 백업을 복원하여 정상 조회 여부를 점검한다.
- 앱 로그에는 이메일, 전체 SN, 매출 원문을 남기지 않는다.

## 10. GitHub와 Vercel 안전 규칙

- GitHub 저장소는 비공개로 만든다.
- `main`은 Vercel 데모 Production 브랜치다.
- 기능 작업은 `feat/<기능명>` 브랜치와 Pull Request로 진행한다.
- Pull Request마다 Vercel Preview를 만든다.
- 저장소에는 `.env*`, SQLite DB, 백업, 업로드, 내보내기 파일을 커밋하지 않는다.
- Vercel에는 `APP_MODE=demo`만 설정한다.
- 데모 모드에서 서버가 로컬 저장소 구현을 초기화하려 하면 배포를 실패시킨다.
- Preview와 Production 모두 Vercel Authentication으로 보호한다.
- 실제 데이터를 촬영한 화면 캡처도 Issue와 Pull Request에 첨부하지 않는다.

## 11. 오류 처리

- Excel 오류는 행 번호, 열 이름, 오류 이유를 표시하되 원본의 민감한 전체 값을 노출하지 않는다.
- 가져오기는 전체 검증이 끝난 뒤 확정하며, 저장 중 실패하면 해당 묶음을 모두 되돌린다.
- SN 중복, 기종별 재고 수량 초과 배정, 출고 장비 재배정을 DB 제약과 서비스 검증 양쪽에서 차단한다.
- 사용자가 취소 가능한 작업과 취소 불가능한 작업을 화면에서 구분한다.
- 삭제 대신 상태 변경과 감사 이력을 우선 사용한다.

## 12. 테스트 기준

- 상태 전이, 수량 계산, SN 중복, 매출 합계를 단위 테스트한다.
- Excel 정상·누락·형식 오류·중복 파일·대용량 제한을 테스트한다.
- 요청 등록부터 배정, 출고, 대시보드 반영까지 통합 테스트한다.
- 로컬 모드와 데모 모드의 데이터 경계를 테스트한다.
- 데모 모드에서 업로드와 실제 데이터 입력이 차단되는지 확인한다.
- `.gitignore`에 실제 데이터 경로가 포함되는지 자동 검사한다.
- 백업 생성과 복원 테스트를 실행한다.

## 13. 1차 완료 기준

- 익명화 요청 Excel을 검증하고 로컬 DB에 등록할 수 있다.
- 기종별 재고 수량을 등록하고 배정 시 요청 수량만큼 SN을 입력할 수 있다.
- 중복 SN과 중복 배정을 차단한다.
- 배정 건을 출고 처리하고 확정 매출을 기록할 수 있다.
- 파트너사·부·팀·영업사원별 수량과 매출을 조회할 수 있다.
- Outlook에 사용할 메일 제목과 본문을 생성할 수 있다.
- 실제 데이터 없이 같은 화면을 Vercel 데모에서 확인할 수 있다.
- 코드와 문서만 GitHub 비공개 저장소에 저장된다.
- 로컬 DB 백업과 복원이 검증된다.

## 14. 1차 범위 밖

- SharePoint 자동 조회 또는 수정
- Outlook 자동 발송
- Entra ID 로그인과 다중 사용자 권한
- Power Automate와 Power BI
- ERP·회계 시스템 연동
- 모바일 앱
- Vercel 또는 외부 DB에 실제 업무 데이터 저장

## 15. 향후 확장 경계

Excel 입력과 메일 출력을 애플리케이션 핵심 규칙에서 분리한다. 추후 권한을 받으면 수동 Excel 입력을 Microsoft Graph 기반 SharePoint 입력으로, 메일 문구 생성을 Graph 기반 Outlook 발송으로 교체할 수 있게 한다. 핵심 요청·재고·배정·출고·매출 모델은 그대로 유지한다.
