# Excel 원본 구조 분석

분석일: 2026-09-17

## 보안 판정

세 파일은 모두 정상적인 `.xlsx` 파일이며 각 파일에 한 개의 시트가 있다. 다만 파트너사명, 담당자명, ITSS 코드처럼 실제 정보로 보이는 값이 남아 있다. 따라서 현재 파일은 로컬 분석에만 사용하고 GitHub 커밋, Vercel 배포, 화면 캡처 공유 대상에서 제외한다.

구현 과정에서는 현재 파일을 테스트 fixture로 복사하지 않는다. 자동 테스트는 같은 열 구조를 가진 완전한 가상 데이터를 코드에서 생성한다.

## 1. 영업 요청 파일

파일: `input-samples/sales-request-anonymized.xlsx`

시트명: `Sheet1`

확인된 열:

| 원본 열 | 앱 필드 | 처리 방식 |
|---|---|---|
| `#` | 원본 행 표시값 | 업무 키로 사용하지 않고 추적용으로만 보관 |
| `월도` | 요청 월도 | `YY.MM` 형식 문자열로 정규화 |
| `ITSS CODE` | 파트너 코드 | 앞뒤 공백 제거 후 문자열로 보관 |
| `Team` | 원본 조직명 | 원문을 보관하고 조직 기준표로 부·팀에 매핑 |
| `파트너사명` | 파트너사명 | ITSS CODE와 함께 파트너 식별에 사용 |
| `담당 DM` | 영업사원 | 조직 기준표와 대조 |
| `Deal Type` | 거래 유형 | 선택형 텍스트로 보관 |
| `End-user` | 최종 고객 | 텍스트로 보관 |
| `현, 사용 Brand` | 기존 사용 브랜드 | 선택 입력으로 보관 |
| `현, 사용기종` | 기존 사용 기종 | 선택 입력으로 보관 |
| `요청 기종` | 요청 ITEM CODE | 모델 기준표와 대조 |
| `요청 수량` | 요청 수량 | 양의 정수, 현재 업무 기본값은 1 |
| `Family` | 제품 Family | 요청 기종과의 일치 여부 검증 |

원본에 신청일, 희망 출고일, 이메일, 단가, 매출 열은 없다. 시스템 요청번호와 가져오기 일시는 앱이 생성한다. 출고일과 확정 매출은 출고 처리 화면에서 관리자가 입력한다.

## 2. 재고 및 배정 파일

파일: `input-samples/inventory-anonymized.xlsx`

시트명: `Sheet1`

한 시트 안에 `Summary`와 `Detail` 두 구역이 있다.

### Summary 구역

| 원본 열 | 앱 필드 | 처리 방식 |
|---|---|---|
| `Family` | 제품 Family | 모델 기준 정보 |
| `ITEM CODE` | 기종 | 재고 수량의 기준 키 |
| `배정 가능 수량` | 입고·생산 누적 수량 | 초기 재고 수량으로 가져오기 |
| `배정 수량` | 기존 배정 수량 | Detail과 대조하는 검증 값 |
| `잔여 수량` | 표시용 잔여 수량 | 앱에서 다시 계산하며 원본 값은 대조에만 사용 |

### Detail 구역

| 원본 열 | 앱 필드 | 처리 방식 |
|---|---|---|
| `Family` | 제품 Family | Summary와 대조 |
| `ITEM CODE` | 기종 | 요청 기종과 연결 |
| `SN` | 배정 SN | 문자열로 변환하고 전체 시스템에서 중복 금지 |
| `보관장소` | 보관장소 | 선택형 텍스트로 보관 |
| `파트너사명` | 배정 파트너사 | 요청과 대조 |
| `배정 월도` | 배정 월도 | `YY.MM` 문자열로 정규화 |
| `배정 여부` | 기존 배정 플래그 | `1`을 배정 완료로 해석 |
| `배정 확인` | 기존 배정 상태 | 기존 이관 검증에 사용 |

Summary의 수량과 Detail의 SN 행은 서로 역할이 다르다. 앱에서는 기종별 재고 수량을 별도로 관리하고, 요청에 배정할 때 SN을 입력하여 배정 장비 레코드를 생성한다. 잔여 수량은 `입고·생산 수량 - 활성 배정 수량`으로 계산한다.

SN은 숫자가 아니라 문자열로 저장한다. 앞자리 `0`, 문자, 하이픈이 포함되어도 원형을 유지한다.

## 3. 조직 및 파트너 기준 파일

파일: `input-samples/organization-anonymized.xlsx`

시트명: `Sheet1`

확인된 열:

| 원본 열 | 앱 필드 | 처리 방식 |
|---|---|---|
| `ITSS CODE` | 파트너 코드 | 파트너 기준 키 |
| `Team` | 원본 조직명 | 부·팀 매핑 전 원문 보관 |
| `파트너사명` | 파트너사명 | 영업 요청 파일과 대조 |
| `담당 DM` | 담당 영업사원 | 영업 요청 파일과 대조 |

현재 파일에는 부와 팀이 별도 열로 나뉘어 있지 않다. 앱은 원본 `Team` 값을 유지하고, 관리 화면에서 부와 팀을 한 번 매핑하도록 한다. 문자열을 임의로 잘라 부와 팀을 추정하지 않는다.

영업사원 이메일 열도 없으므로 조직 매핑 화면에서 선택 입력한다. 이메일이 없을 때는 Outlook `mailto`를 열지 않고 제목과 본문 복사만 제공한다.

## 4. 가져오기 기준

- 헤더는 2행 또는 3행에서 시작할 수 있으므로 고정 행 번호가 아니라 필수 헤더 조합으로 구역을 찾는다.
- 빈 번호 행은 데이터로 가져오지 않는다.
- `Sample` 행도 실제 가져오기에서는 제외하고 미리보기에서 샘플 행으로 표시한다.
- `월도`가 숫자 `26.09`로 저장되어도 `26.09` 문자열로 보존한다.
- 동일 파일 해시를 다시 올리면 중복 경고를 표시한다.
- 요청 중복 후보 키는 `월도 + ITSS CODE + 담당 DM + 요청 기종 + 원본 행 번호`다.
- 중복 후보는 자동 삭제하지 않고 사용자가 가져오기 화면에서 확인한다.

## 5. 구현에 반영할 결정

- 요청 수량은 현재 1이지만 데이터 모델은 1 이상의 정수를 지원한다.
- 재고는 기종별 수량으로 관리하고 SN은 배정할 때 필수 입력한다.
- 확정 매출은 원본에 없으므로 출고 처리에서 입력한다.
- 원본 조직명은 보존하고 부·팀 구분은 별도 조직 매핑으로 관리한다.
- 현재 샘플 파일은 민감 가능성이 있어 Git 추적에서 제외한다.
